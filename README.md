# CS2 / HvH News Monitor

Рабочий MVP мониторинга публичных источников. Уведомления — русский пересказ с объяснением технической важности, фактами из текста и неизвестными деталями. Поддерживаются Telegram и Discord. Назначение этого развёртывания: Telegram, чат `-1004340834224`, тема `70`.

## Что реализовано

- Асинхронный сбор публичных Telegram-страниц, XenForo/vBulletin форумов, RSS/Atom, релизов/коммитов/issues GitHub через официальный API.
- Правила предварительного отбора → модель для семантической классификации и русского пересказа → проверка цитат-оснований → оценка → очередь отправки.
- Дедупликация URL, нормализованного текста, похожих текстов и конкретного события с датой. Копии сохраняются в базе, но повторно не отправляются.
- SQLite в WAL-режиме: публикации, анализ, кэш, источники, ошибки, обратная связь, история отправок. Сохранение состояния и экспоненциальная задержка после ошибок.
- Оценки 0–100; Critical / High Signal / Full Feed / Research; категории и пороги настраиваются. Нет модели — нет автоматических публикаций.
- Команды управления в постоянном Discord-режиме, доступные только ID из `DISCORD_ADMIN_IDS`. Telegram сейчас является транспортом уведомлений: Telegram-команды управления не реализованы.
- Обратная связь даёт ограниченную поправку к категории после минимум пяти решений; не блокирует источники автоматически.
- Найденные внешние ссылки сохраняются как предложения источников; автоматическое подключение неизвестных сайтов не выполняется.

## Архитектура

Один процесс Python 3.11+, asyncio и aiohttp. SQLite подходит для одного монитора и не требует отдельного сервера. Очередь в таблице `posts` переживает перезапуск, отдельный брокер для MVP не нужен. Все сборщики подключены через общий `collect`; анализ, хранение и транспорт независимы. Для нескольких параллельных экземпляров потребуется PostgreSQL с блокировкой задач — этот режим не поддерживается.

```text
botnews/config.py           окружение и режимы
botnews/sources.py          сборщики и ограничения сети
botnews/analysis.py         фильтр, модель, оценки, дедупликация
botnews/storage.py          SQLite и резервные копии
botnews/service.py          планировщик, очередь, отправки
botnews/telegram_sender.py  Telegram Bot API, включая темы
botnews/discord_bot.py      Embed и команды администраторов
botnews/main.py             CLI
scripts/runner_state.py     шифрованное состояние GitHub Actions
sources.json               стартовые источники
tests/                     ключевые проверки
```

Сбор ограничен тремя одновременными запросами, запросы к одному хосту разделены задержкой. Ответы ограничены 2 MB; перенаправления проходят проверку публичного адреса. При 403, 429 или challenge бот записывает ошибку без обхода защиты. Парсеры зависят от разметки сайта. Время публикации должно содержать часовой пояс; неизвестная дата снижает оценку и показывается как неизвестная.

## Источники и реальная проверка

В `sources.json` добавлены все девять запрошенных источников, включая `neverlosecc`. Проверка 10 октября 2026 года на этом компьютере прочитала 49 текстовых Telegram-публикаций: 17 KuCJloTa, 12 Vitma, 20 Neverlose. UnknownCheats вернул 403, три раздела YouGame вернули 429. Снимок результатов: `source_probe.json`. Это результат конкретной проверки, доступность на GitHub runner может отличаться.

| Тип | Ограничения |
| --- | --- |
| Telegram | Только публичный web preview и доступная последняя страница; медиа без текста не анализируются; пропуски возможны при очень активном канале/длительном простое |
| Форумы | Первые сообщения последних 15 тем на первой странице; ответы в старых темах, закрытые разделы и авторизация не поддерживаются |
| RSS/Atom | Последние 30 элементов; качество зависит от полноты ленты |
| GitHub | Последние 10 релизов, 10 коммитов и 10 issues; без токена действует общий лимит анонимных запросов |
| Discord как источник | Не реализован; Discord используется для доставки и администрирования |

Репутация в конфигурации — начальная ручная оценка, не проверенная статистическая гарантия. Neverlose рассматривается как первоисточник собственных изменений; это не независимая проверка его заявлений.

## Бесплатный запуск через GitHub Actions

Workflow `.github/workflows/monitor.yml` проверяет источники дважды в час, на 7-й и 37-й минутах. Это периодическая задача, не непрерывный сервер. В публичном репозитории стандартный runner бесплатен. Плановые запуски могут задерживаться или пропускаться; после 60 дней без активности публичного репозитория расписание может отключиться. [Условия](https://docs.github.com/en/actions/concepts/billing-and-usage), [ограничения расписания](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows).

Для модели можно использовать бесплатный тариф Groq в рамках квот. Обязателен собственный ключ; не включайте платный тариф, если нужен нулевой бюджет. Совместимость API проверена по документации, реальный пересказ требует ключа. [Получить ключ](https://console.groq.com/keys), [лимиты](https://console.groq.com/docs/rate-limits), [API](https://console.groq.com/docs/openai). OpenAI также поддерживается, но его API обычно платный.

1. Добавьте Telegram-бота в группу и разрешите ему отправлять сообщения в нужную тему. Перевыпустите токен, если он был опубликован в чате.
2. В Settings → Secrets and variables → Actions задайте Secrets:
   - `TELEGRAM_BOT_TOKEN` — токен BotFather.
   - `LLM_API_KEY` — ключ Groq или совместимого сервиса.
   - `STATE_ENCRYPTION_KEY` — случайный секрет минимум 32 символа (подготовлен автоматически при развёртывании).
3. Variables: `TELEGRAM_CHAT_ID=-1004340834224`, `TELEGRAM_THREAD_ID=70`, `MONITOR_ENABLED=true`. В этом репозитории они уже настроены. Не меняйте назначение без проверки истории отправок.
4. По умолчанию модель `openai/gpt-oss-120b`, адрес `https://api.groq.com/openai/v1`. Их можно изменить переменными `LLM_MODEL` и `LLM_BASE_URL`. Доступность модели проверена через API Groq.
5. Начальная зашифрованная база для этого репозитория уже подготовлена: после добавления ключа модели очередной запуск заработает автоматически. При самостоятельном развёртывании один раз запустите Actions → News monitor → Run workflow с `initialize=true`. Первая проверка создаёт базу существующих постов, без рассылки старых новостей. В следующих запусках `initialize=false`.
6. Проверьте журнал: сбор, анализ, сохранение состояния должны завершиться успешно. Если доступа к форумам нет, Telegram-сбор продолжает работать.

Состояние хранится в отдельной ветке `monitor-state` в зашифрованном Fernet-файле. Ключ — только в Secrets. Ветка содержит последнюю шифрованную резервную копию; старые коммиты могут сохраняться GitHub некоторое время. Не удаляйте ветку и не меняйте ключ без миграции. Если состояние пропало, бот остановится вместо повторной массовой отправки. Одновременные workflow сериализованы. При принудительной отмене процесса между отправкой и сохранением базы защита от повторов не гарантируется.

Временные сетевые ошибки во время отправки считаются неопределённым результатом: автоматического повтора нет, чтобы не прислать копию уже принятого сообщения. Такие отправки требуют ручной сверки. Следующий запуск повторяет сбор и анализ задач, которые завершились обычной ошибкой.

## Локальный запуск Windows

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
.\.venv\Scripts\python.exe -m pip install --no-deps -e .
Copy-Item .env.example .env
# Заполните .env локально; не публикуйте ключи.
.\.venv\Scripts\python.exe -m botnews.main --telegram
```

Для этого компьютера DNS возвращает fake-IP адреса `198.18.0.0/15` через VPN/TUN. Только при такой настройке включите `ALLOW_FAKE_IP_DNS=true`; на обычном VPS/GitHub оставьте false. LAN/loopback адреса остаются запрещёнными.

CLI:

```powershell
.\.venv\Scripts\python.exe -m botnews.main --probe source_probe.json
.\.venv\Scripts\python.exe -m botnews.main --once
.\.venv\Scripts\python.exe -m botnews.main --publish-once
.\.venv\Scripts\python.exe -m botnews.main --backup data/backup.sqlite3
.\.venv\Scripts\python.exe -m pytest -q
```

`--once` никогда не отправляет сообщения. `--publish-once` выбирает Telegram, если задан его токен; иначе Discord. Не задавайте одновременно несколько CLI-режимов. Для чистого первичного заполнения оставьте `BACKFILL=false`; это не режим проверки пересказов.

## VPS / Docker

```sh
cp .env.example .env
# Заполнить .env. Для Telegram:
docker compose run --rm news python -m botnews.main --telegram
```

Для фонового Telegram-процесса добавьте в сервис `news` строку `command: ["python", "-m", "botnews.main", "--telegram"]`, затем `docker compose up -d --build`. Для Discord используется команда по умолчанию. На Linux каталог `data` должен быть доступен пользователю контейнера (UID 1000). Compose обеспечивает перезапуск и ограничение размера логов. Регулярно создавайте резервные копии через `--backup`; для восстановления остановите процесс и замените файл базы резервной копией.

## Discord-режим (опционально)

Заполните `DISCORD_TOKEN`, `DISCORD_CHANNEL_ID`, `DISCORD_ADMIN_IDS`; пригласите приложение со scopes `bot` и `applications.commands`, разрешениями View Channel / Send Messages / Embed Links. Запуск: `python -m botnews.main`. `DISCORD_GUILD_ID` ускоряет появление команд в тестовой группе; глобальная регистрация может занять время. Читать сообщения Discord бот не просит.

Команды: `/sources`, `/add_source`, `/remove_source`, `/settings`, `/threshold`, `/search`, `/latest`, `/report`, `/rescan`, `/feedback`. Причины отклонений: `advertising`, `config`, `paste`, `duplicate`, `unconfirmed`, `low_significance`, `other`. Полный перечень категорий — в `analysis.py`. `/remove_source` отключает источник с сохранением истории. В Telegram/Actions-режиме изменения делаются через конфигурацию; Discord-команды там не работают.

## Проверка качества и границы MVP

Есть тесты парсеров, фильтра, фактологических оснований, оценки, дубликатов, обратной связи, команд и истории отправок. Проверка реальных Telegram-публикаций отсеяла стримы, конкурсы и бессодержательные сообщения «обновление готово»; крупное обновление Neverlose `Double Precision` прошло предварительный отбор. Это ещё не доказательство точности семантического классификатора: без ключа модели полная проверка пересказов не выполнена. После подключения ключа нужно разметить реальные результаты и проверить пропуски/ложные срабатывания прежде, чем расширять источники.

Факты модель должна связывать с фрагментами исходного текста; проверка присутствия цитаты уменьшает выдумки, но не доказывает смысловую корректность всего пересказа. Независимые подтверждения ищутся только среди собранных публикаций с тем же конкретным событием, на других доменах, с содержательными основаниями. Это эвристика: модель не делает внешний фактчекинг, ссылки сами по себе не считаются подтверждениями. Все Telegram-каналы консервативно считаются одним доменом. Чувствительные утверждения без подтверждений ограничены 74 баллами; высокоприоритетные новости не выдаются лишь за громкий заголовок.

Бот не скачивает вложения, не выполняет найденный код, не использует закрытые данные и не обходит авторизацию. Публикации передаются выбранному провайдеру модели; отправляйте только разрешённые публичные материалы.
